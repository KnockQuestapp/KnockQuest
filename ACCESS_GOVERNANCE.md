# FlutterFlow Access Governance

This runbook prevents recurring "Project Access Restricted" interruptions.

## Permanent Controls

1. Keep one canonical project account for daily work.
2. Maintain at least two admin-capable accounts on the owning workspace.
3. Open the project from the FlutterFlow dashboard list first, then deep-link to pages.
4. Use a dedicated browser profile for this project account only.
5. Remove stale collaborator emails and re-invite only verified active emails.

## Session Hygiene

1. Avoid mixed-account sessions in the same browser profile.
2. If access fails, sign out everywhere and clear FlutterFlow site data.
3. Sign back in with the canonical account and reopen from dashboard.

## Recovery Procedure

1. Click Return Home.
2. Confirm active account email.
3. Reopen project from dashboard.
4. If still blocked, owner re-invites exact email with editor/admin role.
5. Re-test project open from dashboard before using old bookmarks.

## Team Rule

- One project account identity.
- Two admins minimum.
- Dashboard-first open policy.
- Re-invite protocol documented and followed.
